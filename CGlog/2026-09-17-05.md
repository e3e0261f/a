# Cyber-NOte (a) 專案更新日誌 (編號 #05)
日期: 2026-09-17

## 1. 問題與需求清單 (1-8 項)
1. **`a -l --sync` 智慧略過已完整檔案**：在執行同步命令時，系統會自動檢查本地 ledger 是否已存有該檔案的有效短碼 (`key_id`)。若本地資訊已經完整，則**直接略過該檔案的遠端檢查、重複檢索或快取下載**，大幅提升同步效率。
2. **介面排版再次極致美化**：微調表格行寬與對齊參數，將編號統一改為雙位數格式（如 `[01]`, `[02]`），使表格視覺更加工整平衡。
3. **100% 絕對垂直對齊保證**：透過 Rust 精確的欄位寬度運算與符號填充，確保無論終端字型與視窗縮放，外框與欄位皆能完美無瑕地對齊。
4. **極簡短碼展示**：維持 8 位 GPG 短碼呈現，並在無短碼時自動隱藏該欄位，兼顧資訊密度與版面簡潔。
5. **破解推算時間繁體優化**：將部分推算時間說明文字精簡為更符合專業鑑識風格的表達（如「量子抗性 RSA/ECC」）。
6. **快取與網路流量撙節**：未變動或已有短碼的檔案不再觸發任何雲端 API 請求，保護網路與 API 額度。
7. **無縫兼容快速檢索 (`a -l`)**：保留預設 `a -l` 的 0 延遲本地秒開特性。
8. **累積編號日誌持久化**：產出第 5 號日誌，持續完整記錄專案演進脈絡。

## 3. 更改文件大概邏輯與精簡代碼

### A. 智慧略過已完整檔案邏輯 (`src/main.rs`)
- **邏輯**：在 `a -l --sync` 迴圈中，先比對本地持久化紀錄，若 `key_id` 存在且有效（非空、非 `-`、非未知），直接 `continue` 略過，不執行任何網路請求或 GPG 解析。
- **精簡代碼片段：**
```rust
let existing_record = ledger.records.iter().find(|r| r.file_name == filename);
let has_valid_key = if let Some(rec) = existing_record {
    if is_gpg {
        !rec.key_id.is_empty() && rec.key_id != "-" && !rec.key_id.contains("未知")
    } else {
        true
    }
} else {
    false
};

if has_valid_key {
    continue; // ⚡ 略過已完整同步之檔案
}
```

### B. 絕對對齊與雙位數編號排版 (`src/main.rs`)
- **邏輯**：利用 `{:02}` 格式化編號，並設定精確的欄位寬度，確保表格邊框與各欄位 100% 對齊。
- **精簡代碼片段：**
```rust
let idx_str = format!("[{:02}]", idx + 1);
println!("{:<6} {:<34} {:<12} {:<14} {:<40}", idx_str, filename, short_key, size_str, crack_time);
```
