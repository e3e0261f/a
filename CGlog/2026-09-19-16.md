# Cyber-NOte 開發日誌 #16 (2026-09-19)

## 🎯 操作日誌錯誤分析與重大 Bug 修復
針對用戶提供的操作日誌中發生的錯誤，進行分析與代碼修復：

### 🔍 錯誤分析與編號統計 (A-C)
1. **錯誤 A (指令拼寫錯誤 `al`)**：
   - 用戶在終端輸入 `al` 而非正確的 `a -l` 或 `a --list`。雖然在 shell 中可能為 alias 或自定義命令，但在 Rust CLI 中未被識別為標準清單命令。
2. **錯誤 B (指令路由衝突：`--delete` 被誤判為加密命令)**：
   - 根因分析：在 `src/main.rs` 的命令解析中，原本的 `has_encrypt` 判斷使用了過於寬鬆的子字串包含檢測 `(a.starts_with('-') && a.contains('e'))`。
   - 因為 `--delete` 包含了英文字母 `e`，導致當用戶執行 `a --delete 8` 或 `a --delete <文件名>` 時，CLI 錯誤地將 `--delete` 識別為加密請求 (`handle_encrypt_command`)。
3. **錯誤 C (誤判後的連鎖報錯「指定檔案不存在」)**：
   - 因錯誤 B 的路由衝突，CLI 誤以為 `8` 或檔案名稱是本機待加密的檔案路徑，因此在檢查本機路徑時拋出 `❌ 錯誤：指定檔案不存在 -> 8`（或對應檔名）。

### 🛠️ 修復措施
- **收斂加密指令匹配邏輯**：嚴格限定 `has_encrypt` 僅匹配 `-e`、`-ep`、`-se`、`-es`、`--encrypt` 等明確加密標誌，並排除雙破折號長參數（如 `--delete`, `--new` 等含有 `e` 的指令），徹底杜絕指令路由衝突。
- **零錯誤零警告編譯通過**：經 `compile_applet` 與 `lint_applet` 驗證，系統運行狀態完美。
